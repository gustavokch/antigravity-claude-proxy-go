Method
------
mitmdump on 127.0.0.1:18081, allow_hosts scoped to the two Cloud Code hosts,
agy launched with HTTPS_PROXY/HTTP_PROXY pointing at it. Byte-exactness
contract: mitmproxy preserves header name casing, value and received order;
it does not preserve raw wire octets (whitespace, line endings). Evidence
below is header-list exact, not raw-octet exact.

Trust path (differs from plan expectation — NO keychain mutation happened)
--------------------------------------------------------------------------
- Probe A: SSL_CERT_FILE alone. Go client (go1.27 probe) through the MITM:
  TLS-OK 404. Apple curl 8.7.1 (SecureTransport/LibreSSL) without -k:
  404. Both honor SSL_CERT_FILE, so no keychain trust was needed.
- First agy attempt with SSL_CERT_FILE set to ONLY the mitm CA failed at
  the eligibility check (www.googleapis.com is a passthrough host, real
  Google chain, unknown authority). Fix: SSL_CERT_FILE points at a
  combined bundle (system roots + mitm CA). Lesson: SSL_CERT_FILE
  REPLACES the whole root pool on darwin; scope it accordingly.
- mitmproxy CA sha256 (not installed anywhere on this machine):
  5553529cfcaf19b39d515e6daf203b70bc6533c68e0b297d7d27660c8564efea
- Interception proof: agy printed AGY_MITM_OK_20260903 (its --print round
  trip succeeded end to end through the MITM). No cert pinning observed.

Deviations from plan (all recorded, none behavioral for the evidence)
---------------------------------------------------------------------
- Port 18081 instead of 18080: the user's live proxy instance occupies
  127.0.0.1:18080; harness ANTIGRAVITY_MITM_PORT override used.
- allow_hosts regex anchored AND port-tolerant:
  ^(cloudcode|daily-cloudcode)-pa\.googleapis\.com(:443)?$
  mitmproxy 12 matches allow_hosts against "host:port", so a bare anchored
  host regex silently passes everything through as a raw tunnel (verified
  empirically with a debug addon before the capture).
- agy log written to the session scratchpad, not /tmp.
