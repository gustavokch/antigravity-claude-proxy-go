Notes on #12: agy's stable non-alphabetical order (Host, UA, CL, Auth, CT,
AE) is not net/http's writeSubset sort, so agy serializes headers outside
the stdlib request-write path. The proxy is Go net/http; reproducing agy's
exact wire order would require transport restructuring. Upstream demonstrably
tolerates the proxy's current order (JA4 gate passes, calls succeed), so
order-drift is recorded, not fixed, without explicit sign-off.

Notes on #2: agy's UA embeds per-build (cl=) and per-account
(auth_method=consumer) fields; it is not a static constant the proxy can
"sync" verbatim without spoofing those fields.

(2, 6) => per Global Constraints this is a STOP: surface to the user before

Resolution (2026-09-03, user-approved)
--------------------------------------
Decision: strip extras, match agy 1.1.25 exactly (option 2 of the STOP).
Implemented test-first in internal/cloudcode/client.go:

- Removed headers agy never sends: X-Client-Name, X-Client-Version,
  x-goog-api-client, X-Machine-Session-Id, Accept. RequestOptions lost its
  Accept/SessionID fields; the Headers override map remains (anthropic-beta).
- Accept-Encoding identity -> gzip. Manual Accept-Encoding disables
  net/http auto-decompression, so readResponse and DoSSE now decompress
  gzip responses themselves (maybeGunzip, Content-Encoding driven) —
  covered by TestDoJSONDecompressesGzipResponse and
  TestDoSSEDecompressesGzipStream.
- User-Agent restructured to the captured agy literal format:
  antigravity/cli/1.1.25 (aidev_client; os_type=<goos>; arch=<goarch>;
  cl=975399401; auth_method=consumer). Constants now:
  DefaultUserAgentVersion="1.1.25", AgyBuildCL="975399401",
  AgyAuthMethod="consumer". DefaultClientVersion and GoogleAPIClient are
  gone (headers do not exist on the wire).
- Header ORDER not reproduced (order-drift stands): agy's stable
  non-stdlib order would require transport restructuring; Go net/http
  order is accepted upstream.
